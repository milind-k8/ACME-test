# Frontend

How to build the UI. Read [development-process.md](development-process.md) first; this doc only adds what is specific to `packages/web/`. If a component or colour isn't covered here, add it here first and then use it.

## Stack

| Concern | Choice | Notes |
|---------|--------|-------|
| Framework | React SPA, TypeScript strict | Internal tool behind a login, so no SSR / Next.js |
| Bundler | Bun (HTML import from `Bun.serve`) | Started from `bun init --react=shadcn`. Hot reload in dev, no Vite |
| Styling | Tailwind via `bun-plugin-tailwind` | |
| Components | shadcn/ui (Radix) in `components/ui/` | Code lives in the repo; Radix handles focus, keyboard, ARIA |
| Routing | Tiny History-API router in `lib/router.ts` | Three screens don't need `react-router`. Filters live in the URL query string |
| Forms | Plain `<form>` + native HTML validation | `required`, `min`, `type="date"` for instant feedback; server errors shown per field |
| Charts | CSS bars (`BarList.tsx`) | No chart library |
| Tests | `bun test` + `@testing-library/react` + `happy-dom` | |

**shadcn components used:** `Button`, `Input`, `Label`, `Select`, `Table`, `Dialog`, `AlertDialog`, `Card`, `Badge`, `Skeleton`.
**Not used** (they pull in extra libraries): `Form` (react-hook-form + zod), `Chart` (Recharts), `Sonner`, the TanStack data-table.

**Allowed dependencies:** `react`, `react-dom`, `@sentry/react` ([ADR-004](adrs/004-sentry-error-monitoring.md)), shadcn's peers (`@radix-ui/*` per component, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`). Dev: `tailwindcss`, `bun-plugin-tailwind`, `@types/react`, `@types/react-dom`, `@testing-library/react`, `@testing-library/dom` (its required peer), `@happy-dom/global-registrator`.

## Import rules

| Code in… | May import | Must NOT import |
|----------|-----------|-----------------|
| `features/X/` | `components/`, `lib/`, `shared/` | `features/Y/`, `server/` |
| `components/`, `lib/` | `shared/`, each other | `features/` |

Share on the third use: code moves to `components/` only when a second or third feature needs it. Icons and brand marks are the exception: they live in `components/` from the start (see the constants rule in [development-process.md](development-process.md#cross-cutting-conventions)).

## Responsibilities

- `*Page.tsx`: one per screen. Owns data fetching and page state, passes data down.
- Components: presentational, props in and callbacks out. They never call `fetch`.
- `*.api.ts`: the only place a feature talks to the server, always through `lib/api.ts`.
- `components/ui/`: shadcn output. Wrap or compose rather than rewrite, so the CLI can still update them.

## Error handling

Error boundaries only catch errors thrown while rendering. Errors from `fetch` and event handlers are handled in code.

| Error | Handled by | User sees |
|-------|-----------|-----------|
| Render crash anywhere | `Sentry.ErrorBoundary` around `<App/>` in `main.tsx` | Full-page fallback: "Something went wrong" + Reload |
| Render crash inside a page | `Sentry.ErrorBoundary` around the content area in `AppShell`, keyed by route | Fallback in the content area; nav still works, and navigating resets it |
| `401` from the API | `lib/api.ts` → `useSession` clears the session | Redirect to login |
| `400` with `details` | The form | Message under each field |
| `404` / `500` / network failure | The page (`ApiError` from `*.api.ts`) | Inline alert with a Retry button |

- `lib/api.ts` turns every non-2xx response into an `ApiError` (`status`, `code`, `message`, `details`). Pages never inspect raw responses.
- No silent catches: a caught error is either shown to the user or re-thrown.
- `Sentry.ErrorBoundary` works without a DSN, so we don't write our own boundary class.
- **Sentry in production only.** `Sentry.init` runs in `main.tsx` only when the build has `BUN_PUBLIC_SENTRY_DSN` set. `sendDefaultPii: false`; no request or response bodies, so salaries never leave the browser. Expected `4xx` responses are not reported.

## Testing

- **Component** (`*.test.tsx`): behaviour visible to the user (submitting the form shows a field error), not internal state.
- Mock at the `*.api.ts` boundary, never `fetch` inside components.
- **Errors:** a component that throws renders the boundary fallback; an `ApiError` from a page's API call shows the inline alert.

## Adding a frontend slice

1. Types are already in `shared/api-types.ts` (contract first).
2. Add `features/<feature>/`: an `*.api.ts`, a page, and presentational components. Add a nav entry in `AppShell`.
3. List the files in the plan's "As built".

## Design

### Direction

A work tool for someone who looks at numbers all day. It should feel **calm, dense, and trustworthy**, like a well-made spreadsheet rather than a marketing site.

### Foundations

- **Base:** shadcn's default theme (`neutral`), CSS variables in `index.css`. Override only what's listed here.
- **Colour:** neutral grey with one accent (`--primary` = Facebook blue `#166FE5` in light and dark mode; the brand `#1877F2` fails AA with white text, 4.23:1 vs 4.73:1) for primary actions and links. Red only for destructive actions and errors, green only for success toasts. Charts use one hue in different shades.
- **Typography:** Tailwind's default sans. Money columns use **tabular figures** (`tabular-nums`) and are **right-aligned**.
- **Form fields** (`Input`, `Select`, …): no focus halo ring. Focus shows as the border turning `--primary`. Remove shadcn's `focus-visible:ring-*` classes when adding a field component.
- **Spacing:** Tailwind's scale only, no arbitrary values like `p-[13px]`.
- **Dark mode:** supported by shadcn's `dark` class. Light is the default; dark is nice to have.

### Layout

- App shell: left nav (Employees, Insights), header with the user's email and logout, content area.
- Designed for laptops (≥1280 px), usable down to tablet. Phones aren't a goal.

### Patterns

| Need | Use |
|------|-----|
| Employee list | `Table` with sticky header, server-side pagination, filters above the table. Salaries show in their own currency, but sort by USD value; the Salary header says so ("Salary · sorted in USD") |
| Add / edit | `Dialog` with a plain `<form>` (`Input`, `Select`, `Label`). Server field errors under each field. Save disabled while submitting |
| Delete | `AlertDialog` that names the employee |
| Feedback | Own `Toast` for success; inline alert for page-level errors |
| Loading | `Skeleton` rows, never a blank screen |
| Empty state | Short message plus the next action ("No employees match these filters. Clear filters.") |
| Insights | `Table` first, then `BarList` bars labelled with the value |

### Money display

- `formatMoney` (`Intl.NumberFormat`) with the record's currency, e.g. `₹12,00,000`, `€54,000`, `¥6,500,000`.
- USD figures always show the FX date: "in USD, rates as of 2026-10-01".

### Accessibility (minimum bar)

- Every input has a visible label. Placeholders are not labels.
- Fully keyboard-operable, focus always visible, dialogs trap focus and close on Esc (Radix).
- Text meets WCAG AA contrast (4.5:1).
- Errors are never shown by colour alone.
